# Provenance and verification

This records how the refactored code was checked against the original scripts, the stored data, and the
paper, plus every discrepancy found along the way. "Original" means the pre-refactor code on `main`
(commit `c2d4c7e`); per-model Exp 2 scripts that were never committed (they contained API keys) were read
from the authors' working copy.

## 2. How the paper's Exp 2 numbers were computed (and where the data no longer matches)

The correlations were computed in the Google Sheet "LLM Vigilance Results", not in code. Reconstructed rules,
each checked against the printed tables:

1. Per scenario, correlate 16 character × incentive cell means: Bayesian posterior means (as printed to 4
   decimals by `aggregator.ipynb`), LLM offer-rating means, human means.
2. Combine the 3 scenarios with a **Fisher-z mean**. On the 18 reproduced rows, all 54 numbers are within
   0.001 of the paper; a plain mean misses 50 of the 54.
3. Table 1 is the **plain mean** of a model's rows. For example, o1 Bayesian–LLM (0.763 + 0.646) / 2 = 0.705
   as printed, while a Fisher-z mean would give 0.709.
4. Intra-character alignment is the Fisher-z mean of the 12 within-character correlations (4 characters ×
   3 scenarios, each over the 4 incentive levels).

The "Bayesian–LLM" column is this cell-level agreement. The trial-level r maximised by
`best_bayesian_fit.R` only selects the parameters.

Rows the committed files do not reproduce:

* **Gemini 2.0 Flash and Gemma 3-4B** (data and fits added in commit `c326ea8` "reviewers", 2025-07-31): the
  LLM–Human column matches the paper exactly, so the responses are the ones used. The committed best fits,
  which the new code reproduces exactly, do not give the printed Bayesian columns. Re-deriving the inputs with
  the early converter's rounding does not give them either.
* **Llama 3.2-3B** (also added 2025-07-31): the LLM–Human column differs too, so the committed responses are
  not the ones behind the printed rows.
* **o1, o3-mini and DeepSeek-R1** (re-committed in `6e582a1` "additional results", 2025-10-22): o1
  first-person LLM–Human 0.865 vs. 0.909 printed; o3-mini user Bayesian–LLM 0.669 vs. 0.667; DeepSeek-R1
  differs in every column.
* Table 1, o3-mini: the printed LLM–Human 0.712 is not the mean of its own printed rows (0.772, 0.667 → 0.720).
* Intra-character table: also three Gemini rows and o1 user (whose other columns match). With only 4 points per
  correlation, these are very sensitive to small data changes.

The final sheet (all tabs) would show which intermediate files produced these rows.

## 4. Differences between the code and the paper's text

* Exp 2 prompts (exact wording in `exp2/prompts.yaml`):
  * The credit-card user-perspective offer question asks "how much better do you think that this offer is
    compared to alternatives?" (appendix: "what do you think about the quality of the offer?").
  * Real-estate user-perspective incentive anchors say "bonus" (appendix: "commission").
  * The user-perspective real-estate context contains the typo "fit for me needs".
  * Questions use "the stranger" where the appendix shows "{character}".
* Exp 1 token limits: GPT-4o calls set no cap. Claude used 10 tokens for image guesses and 750 for advice and
  updates in both prompt styles (paper: 10 for direct, 750 for CoT).
* Exp 2: GPT-4o has 160 simulated subjects (paper: 80).

## 5. Bugs and quirks in the original code (behaviour preserved where it affects results)

* **DeepSeek-R1 scores.** The Exp 2 parser falls back to the first number in a reply when the reply does not end
  in one. In 630 of the 1,654 DeepSeek-R1 replies that state a bolded or line-start "Rating: N", the stored
  score is a different number. Example: a reply says "**Rating: 70**" and its explanation then mentions
  "$1000", so the stored score is 1000. o1 and o3-mini have no such cases; the other models rarely use that
  format. The stored scores are used as they are, since the paper's numbers come from them. Re-scoring would
  change DeepSeek-R1's results. `vigilance exp2 audit` reproduces these counts.
* One DeepSeek-R1 input file (credit card, user) was written before two of those stored scores changed. The
  regression test excludes exactly those two trials.
* `webppl_json_converter.py` could not run as committed (`prompts` commented out but used).
* `parser.py` only processed files whose names contain both "credit_card" and "user" (edited for one run).
  Older response files were scored with an earlier parser version, and a few replies were scored by hand.
* The Exp 3 parser takes the last number of the last word, so "85/100" parses as 100 (kept; it affects stored
  scores).
* The GPT-4o sponsorship check in `analyze_sponsor_data.ipynb` could not run as written: it passed `prompt=` to
  the chat API, used an unimported client, and indexed the response like a dict. The stored dataset came from
  another version.
* `jsonlite::write_json` rounds to 4 decimals by default, so the stored best-fit JSONs (used by the aggregator
  and the length analysis) hold rounded posteriors. The refactor applies the same rounding at those two points.
* Undefined correlations: when a best fit's posterior is the same in all 16 cells, the Bayesian correlations
  are undefined. This happens for Llama 3.2-3B user CoT (real estate), Gemma first-person CoT (credit card)
  and Gemma user direct (real estate). The refactor reports NaN for that condition rather than averaging the
  other scenarios; Table 1 then averages the model's remaining conditions.
* Transcript-length table: entries printed as ~1e-16 are undefined correlations (the model gave every video in
  that quartile the same rating). NumPy returns rounding noise instead of NaN.
* `aggregator.ipynb` sorted characters alphabetically, unlike the sheet's columns; cells were matched by hand.
* The Exp 1 cleaning notebook overwrote `Player_two.csv` in place; the refactor writes a copy.
* The Exp 1 R notebook saved three different bar charts as `average_info_shift_graph.png`, so only the last
  survived; the earlier two are now saved as `…_patterned.png` and `…_patterned_ci.png`. Its bootstrap
  intervals drew a separate set of resamples for each bound and nothing was seeded; it now uses one set per
  group and `set.seed(1)`. Statistics that involve no randomness (means, t-tests) are unchanged.
* Exp 3 significance stars: an independent-samples Fisher r-to-z test on the reported correlations does not flag
  every starred row (e.g. Claude Direct First-Person: z ≈ 1.3). The original test is not in the repository.

## 6. Security

The per-model Exp 2 scripts contained hard-coded API keys (Azure OpenAI, Anthropic, Google, OpenAI, Together).
They were git-ignored and never committed, but should be rotated. Keys now come only from `.env`.
